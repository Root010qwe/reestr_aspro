# Реестр документов — мини-приложение Аспро.Cloud

Свод по договорам («кто кому сколько должен»), реестр с фильтрами, список того, что проверить,
и приём документов: PDF перетаскивается в приложение, поля заполняются сами, после проверки запись создаётся в списке, а файл ложится в Nextcloud.
Всё — с правами текущего пользователя: список «Реестр документов» (id 8).

## Файлы

- `index.html` — интерфейс (вкладки: свод, реестр, «что проверить», «добавить документ»; `#registry`, `#alerts`, `#add` открывают вкладку по ссылке)
- `js/model.js` — свод и тревоги, без DOM; `js/config.js` — коды полей и вариантов списка 8, реквизиты нашей компании, адрес Worker'а
- `js/parse.js` — разбор документа правилами: тип, номер, дата, контрагент, ИНН/КПП, направление, суммы, НДС, подписи ЭДО, ссылка на договор
- `js/contract.js`, `js/extract.js`, `js/ocr.js` — из doc_aspro: разбор договоров, текст из PDF (pdf.js), распознавание сканов (tesseract.js, бесплатно, в браузере)
- `js/intake.js` — привязка к контрагенту/договору/проекту по реестру, поиск дублей, значения записи, папка в Nextcloud; `js/add.js` — вкладка «Добавить документ»
- `js/portal.js` — доступ к порталу (OAuth из frame SDK, запасной путь через сессию), как в doc_aspro
- `vendor/` — pdf.js (Apache 2.0)
- `worker/reestr-entry.js` — вход: отвечает на POST портала редиректом 303 на Pages
- `worker/reestr-api.js` — загрузка файла в Nextcloud и ИИ-разбор (любой OpenAI-совместимый API); пускает только пользователей портала
- `manifest.json` — права `customlists: full` (чтение и создание записей), `user.me: read`; пункт меню и домашняя страница `app.homepage`
- `tests/model.test.mjs`, `tests/intake.test.mjs` — `node app/tests/…`: свод сходится с актами сверки; разбор 36 реальных PDF совпадает с реестром

## Как работает приём документа

1. Текст из PDF через pdf.js; если текстового слоя нет (скан) — OCR в браузере.
2. Правила (`parse.js`) находят поля. Если чего-то не хватает и подключён ИИ — Worker отправляет текст в модель, ответ дополняет только пустые поля.
3. По ИНН и номеру договора подтягиваются контрагент, проект, договор и направление из уже внесённых документов; дубли (тот же файл или тот же тип+номер+контрагент) подсвечиваются.
4. Карточка подтверждения: пустые обязательные поля подсвечены. «Сохранить» кладёт файл в Nextcloud
   (`<Проект>/<Контрагент ИНН>/<Год>/<ГГГГ-ММ-ДД>_<Тип>_<Номер>_<Сумма>.pdf`) и создаёт запись со ссылкой и хешем файла.

## Развёртывание

1. GitHub Pages: репозиторий `Root010qwe/reestr_aspro` (ветка main, корень; тесты не публикуются — в них данные клиента).
2. Аспро открывает iframe POST-запросом, а Pages на POST отвечает 405. Поэтому вход идёт через Cloudflare Worker `worker/reestr-entry.js`: он отвечает редиректом 303 на Pages. Адрес в `manifest.json`: `https://reestr-entry.trinos-881.workers.dev/`.
3. Worker `reestr-api` (`worker/reestr-api.js`): Cloudflare → Workers → Create → вставить код → Deploy. В Settings → Variables:
   - секреты `NC_USER` (`bot_aspro@nb.ru`), `NC_PASS` (пароль приложения Nextcloud бота), при необходимости `AI_KEY`;
   - переменные `NC_URL=https://nextcloud.it-nb.ru`, `NC_ROOT=КазГАУ реестр документов/Реестр`, `PORTAL=https://aspro.it-nb.ru`, `ORIGIN=https://root010qwe.github.io`;
   - для ИИ: `AI_BASE_URL` (например `https://open.bigmodel.cn/api/paas/v4` для GLM) и `AI_MODEL` (например `glm-4-flash`). Без `AI_KEY` работают только правила.
   Адрес Worker'а — в `js/config.js` (`intake.api`) или в настройке приложения `{"intake":{"api":"…"}}`.
4. Аспро.Cloud → Приложения → Кабинет разработчика → приложение из `manifest.json`; после смены прав — обновить установленную версию.
5. Доступ к списку «Реестр документов» (настройки списка → Пользователи) — тем, кто смотрит свод и добавляет документы.

Локальная проверка без портала: `index.html?demo=<файл.json>` — выгрузка элементов списка в формате API.

## Правила свода

- **Закрыто** — сумма УПД / актов выполненных работ / актов сдачи-приёмки по договору.
- **Оплачено** — сумма платёжных поручений по договору.
- **Расчёты** = закрыто − оплачено: у доходного договора > 0 — нам должны, у расходного — мы должны; < 0 — аванс.
- Документы без договора группируются по контрагенту и проекту.
